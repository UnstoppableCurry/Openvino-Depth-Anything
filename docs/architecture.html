类型关系

Depth 公有继承 OpenvinoEngine。入口不叫 main，而叫 maindepth。

符号 文件 源码里做的事

OpenvinoEngine：读模型与预处理

构造函数 OpenvinoEngine(xml, device) 会调用 compileModel() 和 createInferRequest()。另有一个三参数构造函数会按行读取一个文本文件到 keys；Depth 没有使用这个重载。

compileModel() 里的 PrePostProcessor 按源码原文是：

  • 输入 tensor：u8，布局 NHWC，颜色 BGR
  • 预处理：转到 f32，颜色转到 RGB，scale({255., 255., 255.})
  • 模型布局：NCHW
  • 输出 tensor：f32
  • 随后 core_.compile_model(model, device_)

头文件包含 <windows.h>，三参数构造函数里调用 SetConsoleOutputCP(CP_UTF8)。这是 Windows API，不是跨平台抽象。

OpenvinoEngine::inference 用传入的 float* 建 ov::Tensor，set_input_tensor 后同步 infer()，再按 n 取多个输出指针。

实现细节（仍只来自源码）

compileModel() 把 OpenVINO / 标准 / 未知异常打到 cerr 或 cout。失败时函数返回，调用方仍可能继续使用未成功编译的成员。

Depth::inference 没有走基类那个 inference(float*, int)，而是自己对 infer_request_ 做一次同步推理。

Depth：填充、推理、伪彩色

paddingAndResize 定义在 depth.h：先按长边补黑边成正方形，再缩到 img_len × img_len。depth.cpp 顶部有一份几乎相同的实现，整段被注释掉。

restoreOriginalImage 先把图缩回“原尺寸 + padding”，再按 ROI 裁掉填充。

Depth::inference(cv::Mat img, int h, int w) 的顺序是：

  1. paddingAndResize(img, w)
  2. 把填充后的 data 指针送给 OpenVINO
  3. 取输出 float*，按 h × w 拷进 CV_32FC1 的 cv::Mat
  4. normalize 到 0–255 的 CV_8UC1
  5. applyColorMap(..., COLORMAP_INFERNO)
  6. restoreOriginalImage 后返回

maindepth() 调用时传入的 h 和 w 都是 518，与 README 里 Model Optimizer 的 [1,3,518,518] 一致。
